# Reports

Reports combine evidence into conclusions or recommendations. Their inputs are
listed here so a reader can trace every report back to its case studies and
supporting sources.

| Report | Evidence inputs | Role |
| --- | --- | --- |
| [Case study synthesis](case-study-synthesis.md) | Four [workflow case studies](../case-studies/README.md#workflow-case-studies), plus named supporting sources | Concise comparison and combined design conclusions |
| [Common patterns across the four studies](common-patterns.md) | The same four workflow case studies, cross-checked against additional mature projects | Detailed evidence matrix, shared model, and minimum skeleton |
| [Recommended spec-driven document layout](recommended-layout.md) | Cross-case reports, the [Full Stack FastAPI layout study](../case-studies/full-stack-fastapi-template.md), and the GPT-5.6 Sol supporting report | Actionable repository structure, lifecycle, and quality gates |
| [GPT-5.6 Sol guidance and practitioner pitfalls](gpt-5.6-sol-agent-guidance.md) | Official OpenAI guidance and practitioner reports | Supporting harness research; not derived from the workflow case studies |

The first two documents are reports generated directly from the four workflow
case studies. The recommended layout is the final design report that applies
their conclusions together with the two clearly identified supporting inputs.
